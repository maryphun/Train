# Battle cut-in ribbon artwork

## User request

The user supplied a manga cut-in reference and requested the effect without its character,
because their character photo is already available. They then explicitly requested removing
the right-side **ブチッ** lettering, making the **middle black**, and making the **top and
bottom transparent**. This revision supersedes the initial transparent-center interpretation.

## Asset

- `Assets/Graphic/UI/BattleCutInRibbon.png`: 1619 × 971 RGBA PNG generated by the built-in
  imagegen tool. Broad black diagonal band, rough white torn edges, no character or lettering.
- Saved pixels are copied unchanged from the generated output; no local image editing.
- Unity import: **Sprite (2D and UI)**, **Single**, **Full Rect**, centered pivot, no borders,
  no mipmaps, no texture compression, bilinear filtering and Clamp wrapping. Generated alpha
  is retained with **Alpha Is Transparency**.
- Alpha inspection confirms empty top/bottom samples have alpha 0; central black samples
  have alpha 254 (approximately 99.6% opacity). The generator leaves small edge variation.
- This source image remains static. The user subsequently confirmed the loop animation
  described below. Character-photo assignment, scene wiring and automatic masking remain
  unconfigured.

For a Unity UI Image, assign this sprite, use **Image Type = Simple**, keep the Image color
white with full alpha, and disable **Raycast Target** if it is only decorative. Preserve
Aspect retains the generated proportions. The ribbon's center is black, so a portrait should
be layered above it; the ribbon itself does not automatically clip the portrait.

The live Battle Trello card was refreshed and contains no additional artwork requirements.

## Confirmed 10-frame loop

The user explicitly confirmed **10 frames**, **rippling torn edges**, a **fixed black center**,
**0.8 seconds per loop**, and **programmatic generation from the existing PNG**. This is an
authorized pixel-editing exception to the default imagegen workflow; no new imagegen/API
calls were made for the animation.

### Deliverables

- `Assets/Graphic/UI/BattleCutInRibbonLoop/BattleCutInRibbon_01.png` through
  `BattleCutInRibbon_10.png`: exactly 10 distinct full-resolution **1619 × 971 RGBA** frames.
  Each is a Single UI sprite with its own metadata, matching import settings and centered pivot.
- `Docs/Previews/BattleCutInRibbonLoop.png`: full-resolution **animated PNG**, true alpha,
  all 10 frames, infinite looping. Unity imports animated PNGs as static textures; use the
  separate sprite frames for Unity playback.
- `Docs/Previews/BattleCutInRibbonLoop.gif`: animated preview at 960 × 576, with a checkerboard
  background to show the transparent regions. The checkerboard is only in this preview.
- `Docs/Previews/BattleCutInRibbonLoop.json`: frame order, asset GUIDs, timing, source hash
  and generation/verification measurements.

Playback order is **01 → 02 → … → 10 → 01**, with **80 ms per frame** (**12.5 fps**).
In a Unity UI animation, animate the ribbon Image's **Sprite** property using those frames
in that order, with key times **0, 0.08, 0.16, …, 0.72 seconds**. Put frame 01 at the
**0.8-second boundary** to close the clip, and enable **Loop Time**. This boundary key reuses
frame 01; it is not an eleventh distinct image. Keep the portrait on its own UI object.

### Motion and verification

Only the top and bottom edge regions are resampled. Two travelling sinusoidal ripples span
the ribbon width, with the lower edge a quarter-cycle out of phase with the upper edge.
The source's median white-edge thickness is 18 pixels. Deformation amplitude is 35% of that
thickness (6.3 pixels), and its influence tapers smoothly to zero 54 pixels from each edge.
Subtracting the initial phase keeps frame 01 identical to the source pixels. Premultiplied-alpha
interpolation preserves the edge colors; the central pixels and areas outside the deformation
regions are copied unchanged. The phase repeats exactly at one complete cycle.

Verified 10 distinct frames, consistent dimensions, unchanged **362,960 central pixels**,
transparent corners, and an exact virtual end/start match. The frame 10 → 01 transition has
approximately the same measured change as frame 01 → 02. Decoding the animated PNG reproduces
all exported frames exactly, including alpha. Both animated exports contain 10 frames, repeat
indefinitely and use 80 ms per frame. Preview/artwork were inspected. The original PNG remains
unchanged. Unity scene playback is not configured by this artwork task.

## Final generation prompt

Mode: built-in imagegen edit, `transparent_background = true`. Edit target: the supplied
original reference image. Earlier discarded iterations are not imported into the project.

User-requested changes: (1) Remove the large Japanese sound-effect lettering ブチッ on the right completely, including its black outlines and extra detached text strokes. (2) Remove every part of the character and fill the entire central diagonal band with SOLID OPAQUE BLACK ink (RGB 0,0,0, alpha 255). (3) Make the entire region ABOVE the top torn white border and BELOW the bottom torn white border fully transparent alpha 0. Keep the reference's broad irregular diagonal band, sloping upward from lower left to upper right, and preserve the rough white torn-paper borders along both edges. The delivered object is ONE SOLID BLACK DIAGONAL RIBBON with opaque white rough ripped edges, floating on actual transparent background. The central black ribbon is the foreground subject and MUST REMAIN BLACK AND FULLY OPAQUE. There is no transparent window through its middle. Top and bottom outside the ribbon are completely empty transparency, with no black panels, no shadows and no glow. Extend the ribbon to the left and right canvas boundaries. Clean, flat pure black-and-white manga ink; crisp edges with only narrow antialiasing, no gray speckle artifacts. No characters, no people, no eyes, no face, no hair, no skin, no clothing, no remaining Japanese text, no letters, no symbols, no sound-effect text, no logo, no watermark, no painted checkerboard. Maintain the original landscape composition. Return one finished reusable RGBA PNG sprite.
